# Модуль перевода: итог на 13 ноября 2026

Поддерживаются Google без ключа, Yandex Cloud и офлайн Argos. MyMemory отсутствует в каталоге, настройках и коде провайдеров. Базовая версия для сравнения — `84931aa`; замеры до и после сделаны в этой сессии на исходнике №6. Исходный файл, OCR, группировка и масштаб не менялись.

## Результаты на №6

Windows OCR распознал 28 строк, после группировки получено 11 уникальных текстов. Изображение — 609 × 790, SHA-256 `2a0f24357b3825db3d9b1ad4f14582337a8f6869642df1d440914b4f13b83ff0`. Параметры: en → ru, гибрид и доработка фрагментов выключены, стандартный бюджет 15 секунд. Компьютер: Ryzen 5 7640HS, 6 ядер / 12 потоков, Python 3.11.9.

Два полных прогона каждого варианта. В каждой ячейке приведены оба измерения, секунды; это наблюдения, а не гарантированная задержка сервиса.

У Google и Yandex по одному HTTP 200 на кадр, у Argos сетевых запросов нет. Ошибок запросов и пайплайна нет. Между обычными прогонами создаётся новый `Translator`: его текстовый кэш пуст, сетевой клиент новый. SSL-контекст сертификатов общий для процесса, поэтому его первоначальную загрузку оплачивает только первый клиент. DNS, соединения системного прокси и кэш удалённого сервиса контролировать нельзя.

Отдельный замер использует один и тот же результат Windows OCR для всех провайдеров. Хэш текстового пакета до/после совпал: `1c40eb87007a8f65dafcbc7fbc887040753ef432b05aa95114adfffb250de24c`. Здесь измеряется только вызов модуля перевода, миллисекунды:

| Переводчик | Первый вызов до → после | Открытый клиент/модель, кэш очищен: до → после | Текстовый кэш после |
|---|---:|---:|---:|
| Google | 2752 → 750 | 183 → 89 | 0,20 |
| Yandex | 1702 → 931 | 840 → 1225 | 0,16 |
| Argos | 6569 → 2865 | 5319 → 2274 | 0,13 |

Повторный запрос Yandex в этом замере оказался медленнее исходного. Сетевая задержка меняется; ускорение загрузки клиента не означает ускорения обработки запроса на стороне сервиса. Мгновенный повтор Google по открытому соединению тоже может использовать удалённый кэш: это не прогноз для нового текста.

Повторный **кадр** отдельно проверен для всех шести прогонов: кэш сработал. Обработка кадра заняла 4–7 мс и показ 1,7–2,4 мс, кроме одного выброса обработки Google до 58,6 мс. Текстовый кэш и кэш кадра — разные механизмы.

Проверка настоящего асинхронного окна с OCR и переводом завершилась без таймаутов: Google — 2,69 с, Yandex — 2,85 с, Argos — 3,96 с. Максимальный интервал между GUI heartbeat — соответственно 109 / 94 / 109 мс. Эти проверки обходят обычную подготовку компонентов и включают первый холодный вызов. В приложении HTTP-клиент и модель готовятся заранее в рабочем потоке.

## Применённые изменения

- **HTTP/TLS.** Профиль показал примерно 0,9–1,1 с на создание клиента: один и тот же набор сертификатов загружался заново для основного транспорта и прокси. Теперь SSL-контекст переиспользуется по настройкам `SSL_CERT_FILE` / `SSL_CERT_DIR`, с ограничением кэша до четырёх вариантов. Проверка сертификатов, приоритет пользовательских CA, прокси и HTTP/2 сохранены. Контрольный запуск: первый клиент 385 мс, следующие 0,63 и 0,41 мс. Это локальная подготовка, без сетевого запроса. Исходный профиль имеет накладные расходы cProfile; сравнение приблизительное.
- **Google.** Некорректный отдельный элемент ответа повторяется отдельно; успешные соседние элементы сохраняются. Неверное число элементов по-прежнему отклоняет пакет целиком, поскольку безопасно сопоставить его с исходниками невозможно. Пакеты до 4000 символов / 16 частей, максимум две сетевые задачи; сохранены резервные адреса, паузы после ошибок и `Retry-After`.
- **Yandex.** Для API-ключа сервисного аккаунта `folderId` необязателен. Если он задан, поле передаётся как раньше. Сохранены пакеты до 10 000 символов, два запроса одновременно, проверка порядка и числа результатов, общий cooldown между захватами.
- **Argos.** Длинные английские абзацы разбиваются на предложения лёгким правилом, без загрузки NLP-модели. На №6 получилось 19 сегментов из 11 исходных регионов; все кодируются и переводятся одним вызовом CTranslate2, затем собираются обратно к своим регионам. Учитываются распространённые сокращения, инициалы и обозначения вроде `No. 6`, `U.S. Navy`; для других исходных языков сохранено разбиение по длине. Части ограничены 1000 символами. Успешный регион сохраняется при повреждённом результате другого региона.
- **Резерв.** Основной переводчик получает общий бюджет за вычетом `min(5 с, timeout / 3)`. Оставшееся время доступно резервному при ошибке, в том числе таймауте основного. Отмена не запускает резерв. Обработке уже готовых регионов не мешает истечение времени на других регионах.
- **Кэш.** Нормализация и дедупликация выполняются до отправки. Полный основной перевод хранится в ограниченном LRU: 2048 записей и 1 млн символов источников + переводов. Частичный перевод и результат резерва живут 30 секунд; срок передаётся кэшу кадра, поэтому резервный результат не закрепляется навсегда. Ошибки не кэшируются. Добавлен `clear_cache()` для сброса и честных замеров.
- **Параллельные вызовы.** Один `Translator` обрабатывает один кадр за раз: повторный конкурентный вызов использует заполненный кэш, вместо повторной отправки тех же текстов. Ожидание учитывает отмену и время кадра. Внутри кадра остаётся ограниченный параллелизм провайдера.
- **Бюджет и закрытие.** Сетевые провайдеры используют общий `NetworkProvider`. Бюджет проверяется при чтении частей ответа; декодированный ответ ограничен 2 МиБ. Закрытие запрещает новые запросы, отменяет очередь, закрывает клиент/пул или выгружает модель. Повторное открытие закрытого экземпляра запрещено, повторный `close()` допустим. Проверяются некорректные таймауты, пустые ответы и индексы частей.
- **Диагностика и очистка.** Убраны ветка разбиения по UTF-8-байтам, оставшаяся от удалённого провайдера, дублирование сетевых ресурсов и динамические поля `_google_provider` / `_yandex_provider` / `_argos_provider`. Импорт Tk-диалогов Argos отложен до установки модели. `last_stats` и журнал содержат время, HTTP-запросы, попадания в кэш, число резервных, неполных и ошибочных результатов.

Применение собственного проверяющего SSL-контекста описано в [документации HTTPX](https://www.python-httpx.org/advanced/ssl/). Ограничение таймаутов по отдельным операциям/частям ответа — в [HTTPX Timeouts](https://www.python-httpx.org/advanced/timeouts/). Необязательность каталога для сервисного API-ключа — в [Yandex Translate API](https://aistudio.yandex.ru/en/docs/translate/api-ref/Translation/translate).

## Проверенные настройки Argos

Модель, `int8`, beam=2 и число потоков оставлены прежними. Уменьшение длины сегментов дало преимущество без снижения beam. Следующие однократные сравнительные запуски относятся только к вычислению Argos на одинаковом пакете, с уже загруженной моделью:

| Размер батча, токенов | Beam | Время, мс |
|---:|---:|---:|
| 1024 | 2 | 5713 |
| 512 | 2 | 6075 |
| 256 | 2 | 6886 |
| 128 | 2 | 7407 |
| 128 | 1 | 6601 |

| Intra / inter threads | Время, мс |
|---:|---:|
| 1 / 1 | 12508 |
| 2 / 1 | 8117 |
| 4 / 1 | 5520 |

После разбиения на предложения в отдельной пробе — 2497 мс. Поэтому дефолт остаётся intra=4, inter=1, max batch=1024, beam=2. Эти значения не универсальны для другого CPU или GPU; переменные `ARGOS_*` доступны для настройки. Общие принципы квантования, потоков и пакетирования приведены в [CTranslate2 Performance](https://opennmt.net/CTranslate2/performance.html).

## Контракт и ограничения

Рабочая точка входа — `Translator.translate_many(texts, cancel=None) -> dict[str, str | Exception]`. Ключ — исходный текст с обрезанными краевыми пробелами; разные исходные переносы могут иметь общий нормализованный запрос. Пустые источники пропускаются. Провайдеры возвращают по одному элементу на каждый входной текст, сохраняя порядок. Неверные аргументы и вызов закрытого экземпляра вызывают исключение; ошибки отдельных переводов возвращаются в соответствующих значениях.

`warmup()` подготавливает основной клиент без отправки текста, а для Argos ещё загружает модель. `close()` освобождает ресурсы; приложение вызывает освобождение в рабочем потоке. Очередь не может запустить новые запросы после закрытия. Уже начатая системная сетевая операция завершается по своему transport timeout; синхронный вызов CTranslate2 нельзя принудительно прервать внутри нативного кода. Его отмена проверяется до и после декодирования. Для жёсткого прерывания посреди вычисления нужен отдельный процесс с перезапуском модели; здесь такой механизм не добавлялся.

Google использует неофициальные веб-адреса без ключа. Работа без ограничений не гарантируется: формат, доступность и лимиты могут измениться. Повторные попытки и cooldown сокращают лишние запросы, но не устраняют ограничения сервиса. У Yandex сохраняются квоты и сетевая задержка.

Google и Yandex на контрольном пакете вернули те же тексты до и после правок. У Argos формулировки изменились при разбиении предложений: буквальная идентичность и неизменное качество не гарантируются. Словарь, двусмысленность без контекста и ошибки исходного OCR остаются ограничениями модели. Например, Windows OCR читает `units` как `tmits`, а грузоподъёмность распознаёт с ошибкой; переводчик не получает правильного исходного текста.

Отсутствие ошибок HTTP не означает правильный перевод каждого слова или полное покрытие страницы. Мелкая подпись под фотографией на №6 разбита OCR на мусорные фрагменты; в итоговых PNG остаются участки оригинала и неудачные переводы. Google/Yandex дополнительно пропускают один блок при проверке пересечений оверлея. Эти проблемы относятся к OCR/группировке/наложению и в этом изменении не исправлялись. В обычном кадре после ускорения Google заметны затраты на подготовку оверлея — примерно 0,64–0,83 с; это следующий самостоятельный участок оптимизации.

# Один результат OCR для всех, первый / повтор без кэша / кэш

.venv\Scripts\python.exe benchmarks\check_responsiveness.py --provider google --image C:\Users\qwert\OneDrive\Desktop\исходное-6.png

Для полного прогона нужен Windows OCR en-US, для Yandex — `.env` с ключом, для Argos — optional-зависимости и установленная модель en → ru. Онлайн-запуски расходуют квоты. Файл изображения заменяет захват экрана: `total_ms` включает OCR, обработку, перевод и показ, но исключает чтение файла, создание OCR и захват MSS. Подготовка фона пересекается с переводом, поэтому времена стадий нельзя просто сложить.

Исходные JSON/PNG сохранены локально в исключённом из Git `test/benchmarks/translation-final-before` и `test/benchmarks/translation-final`. Сводка, тексты контрольного пакета, переводы, версии библиотек и результаты экспериментов сохранены в отслеживаемом `benchmarks/results/translation-final-2026-11-13.json`. Промежуточные `translation-final-after` и `translation-module-after` — исследовательские прогоны до последней правки TLS; для итогового сравнения используются именно `translation-final` и `translation-module-final`.
