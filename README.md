# TranScr — прототип экранного переводчика

Текущий прототип выполняет последовательность: захват всего виртуального рабочего стола → OCR → перевод → вывод в консоль. Захват и OCR уже разделены на отдельные модули; переводчик имеет единый простой интерфейс, поэтому его можно расширять независимо от остальных частей приложения.

## Запуск в Windows 10+

1. Установите Python 3.10 или новее и откройте командную строку в папке проекта.
2. Создайте виртуальное окружение и активируйте его:
   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```
3. Установите базовые зависимости:
   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
4. Запустите программу:
   ```powershell
   python main.py
   ```
5. Выберите OCR. По умолчанию — Windows OCR; ему нужен установленный в Windows языковой пакет распознавания английского.
6. Выберите переводчик. Нажатие Enter выбирает MyMemory. Выбор задаётся при каждом запуске. После запуска `Alt+T` делает захват, `Esc` завершает работу.

Google больше не используется: его неофициальный endpoint отвечал `429 Too Many Requests`. `deep-translator` — это библиотека-обёртка, а не самостоятельный переводчик; её Google-адаптер может столкнуться с тем же ограничением. Для установки без ключей проект использует HTTPS API сервиса MyMemory напрямую, не добавляя лишнюю зависимость. Анонимная квота невелика; переменная `MYMEMORY_EMAIL` может увеличить доступный дневной лимит. Текст делится на блоки до 450 символов, до трёх блоков обрабатываются параллельно, а последние 64 результата кэшируются в памяти.

## Альтернативные переводчики

Перед настройкой скопируйте `.env.example` в `.env` (в PowerShell: `Copy-Item .env.example .env`) и измените только те значения, которые нужны выбранному сервису.

- **MyMemory (пункт 1, по умолчанию):** не нужен API-ключ. Чтобы увеличить дневную квоту, укажите email в `MYMEMORY_EMAIL`. У сервиса остаются ограничения и качество может отличаться от крупных машинных переводчиков, поэтому это удобный вариант для проверки прототипа, но не гарантированно безлимитный переводчик.
- **Baidu Translate (пункт 2):** отдельный API. Зарегистрируйтесь на [Baidu Translate Open Platform](https://fanyi-api.baidu.com/), включите общий текстовый перевод и заполните `BAIDU_APP_ID` и `BAIDU_API_KEY`. Код автоматически разбивает большой текст на небольшие запросы и учитывает ограничение стандартного тарифа по частоте запросов.
- **Yandex Cloud Translate (пункт 3):** заполните `YANDEX_API_KEY` и `YC_FOLDER_ID`. Нужны доступ к Yandex Cloud Translate и интернет.
- **Argos Translate (пункт 4):** установите дополнительные зависимости `pip install -r requirements-optional.txt`, затем выберите пункт 4. При необходимости можно установить локальный файл модели `.argosmodel` для пары языков `en → ru`. Предупреждение `Language en package default expects mwt, which has been added` — не ошибка перевода, если результат успешно появился; это сообщение инициализации языкового конвейера.
- **Гибридный режим (пункт 5):** сначала пробует MyMemory, при сбое использует установленную модель Argos. Для офлайн-перевода Argos и модель должны быть установлены заранее.

Не добавляйте заполненный `.env` в архивы или репозиторий: в нём хранятся секретные ключи.

## Структура текущего прототипа

```text
core/
  application.py          # запуск и связь модулей
modules/
  capture/
    screen_capture.py     # захват всего виртуального рабочего стола
  ocr/
    base.py               # общий интерфейс OCR
    types.py              # распознанный текст и координаты
    ocr_worker.py         # выполнение OCR в отдельном потоке
    windows_ocr.py        # OCR средствами Windows
    paddle_ocr.py         # дополнительный OCR
  translation/
    translator.py         # маршрутизация, гибридный режим и кэш
    mymemory.py           # MyMemory через HTTPS API
    baidu.py              # официальный Baidu Translate API
    yandex.py             # Yandex Cloud Translate
    argos.py              # офлайн-перевод и установка модели
    text_chunks.py        # разбиение текста для API с ограничениями
test/
  test_translator.py      # тесты выбора переводчика и кэша
  test_translation_providers.py # тесты провайдеров и разбиения текста
  test_ocr_worker.py      # тесты фонового OCR-потока
  screenshots/             # снимки для отладки (создаются при запуске)
main.py
requirements.txt
requirements-optional.txt
.env.example
```

Скриншоты захвата сейчас сохраняются в `test/screenshots/` для отладки. Перед публикацией проекта их стоит удалить: на них может быть личная информация с экрана.

## Тесты

Тесты маршрутизации перевода не обращаются к интернету и не требуют установленных API-ключей:

```powershell
python -m unittest discover -s test -p "test_*.py" -v
```

## Что пока не реализовано

Выбор области и нескольких прямоугольников, real-time режим, детектор изменения картинки, фильтры/определение языка, скоринг OCR, оверлей, камера, графический интерфейс настроек, менеджер пакетов и прокси. Кэш перевода сейчас простой и хранится только в памяти процесса; постоянный кэш OCR, стилей и изображений ещё не реализован. Текущий захват сканирует весь виртуальный рабочий стол. Эти возможности лучше добавлять отдельными модулями после стабилизации прототипа.
